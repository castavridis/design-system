# brand-experiment

Turn this repo's design tokens into new, on-brand experiments — fast. Two paths:

- **Here (Claude Code):** scaffold a self-contained on-brand Artifact directly.
- **There (Claude Chat / anywhere without this repo):** generate a portable
  **brand brief** the user pastes into a conversation, so that Claude has every
  token, font and rule inlined and stays on-brand without a package install.

This is a *consumer* of the tokens, not another source of truth. It never
invents colours, spacing or type — it reads the built artifacts. The one
writable token source is `src/pmndrs-design-book.ts`; everything in `dist/` is
generated by `pnpm build`. See [figma-token-sync](../figma-token-sync/SKILL.md)
for the token pipeline itself.

## Always build first

The brief and any scaffold read from `dist/`, so it must be current:

```bash
pnpm build
```

## Path A — portable brief for Claude Chat (the default ask)

Generate one self-contained document with every value inlined:

```bash
node .claude/skills/brand-experiment/scripts/make-brief.mjs
```

This writes `dist/brand-brief.md` (git-ignored, regenerated). It packs, straight
from `dist/`: the webfont `@import`, the paste-ready `:root` token block, the
colour table (OKLCH + hex + role), the type roles, spacing/radius, the gradient
rules with worked examples, and the [design language](references/design-language.md).
Nothing is transcribed by eye — colours/gradients come from the built module, so
the brief can't drift from source.

Then tell the user: **copy the whole file into a Claude Chat conversation**, and
ask for what they want on top of it (e.g. *"Using the pmndrs brand kit above,
build a single-file HTML hero for a fictional WebGL library"*). Print the path
and offer to show it. Use `... make-brief.mjs -` to print to stdout instead.

## Path B — scaffold an Artifact here

When the user wants the experiment built *now*, in this session:

1. `pnpm build`, then read `dist/tokens.css` (the `:root` block) and
   `dist/fonts.css` (the `@import`) — inline **both verbatim** into the artifact.
2. Load the **`artifact-design`** skill first (as its own guidance requires),
   then write the HTML/Markdown file and publish with the **Artifact** tool.
3. Style **only** through the `var(--…)` custom properties. Never hardcode a hex
   that duplicates a token. For canvas/WebGL that can't read custom properties,
   pull literal OKLCH values from `dist/tokens.json`.
4. Follow the [design language](references/design-language.md): warm neutral
   ground, 1–2 accents per view, one confident gradient, serif headlines over
   sans body, 16px rhythm and rounding.

## The brand in one breath

Details (and exact values) are in the generated brief and the
[design language](references/design-language.md). The shape of it:

- **Grounds:** `brand.dark` (warm near-black) and `brand.light` (warm off-white)
  — *not* pure black/white, and *not* gradient stops.
- **Accents:** purple (signature), red, orange, yellow, green, teal, blue. Spend
  them sparingly against the ground.
- **Type:** Faculty Glyphic serif for display, Geist sans for body/UI, Geist Mono
  for code/data.
- **Rhythm:** 16px base space; 16px radius (aliased to space). Soft, generous.
- **Gradient:** one house pattern — 3 stops at 16/50/84%, accents only, no two
  adjacent the same. `gradient()` / `randomGradient()` in `dist/tokens.js` build
  legal ones.

## Guardrails

- **Read tokens, don't restate them.** Always regenerate from `dist/` rather than
  pasting values from memory — they may have changed.
- **Never edit `dist/` or `src/` here.** This skill only consumes tokens. Token
  changes go through `src/pmndrs-design-book.ts` + `pnpm build`.
- **Stay on-brand, not just colourful.** Restraint is the brand: neutral ground,
  few accents, one gradient. A rainbow of all seven accents is off-brand.
- The token set has **no light/dark theming** — `brand.dark`/`brand.light` are two
  neutral brand colours, not modes. Don't build a theme toggle off them.
