Introduction

@react-three/fiber is a React renderer for three.js. Build your scene declaratively with re-usable, self-contained components that react to state, are readily interactive and can participate in React's ecosystem.

Critical content demanding immediate user attention due to potential risks.

Does it have limitations?

None. Everything that works in three.js will work here without exception.

Is it slower than plain three.js?

No. There is no overhead. Components render outside of React. It outperforms three.js at scale, thanks to React's scheduling abilities.

react-ts 
import { Canvas } from '@react-three/fiber'
import { Cloud, CameraControls } from '@react-three/drei'

export default function App() {
  return (
    <Canvas camera={{position: [0,-13,0]}}>
      <Cloud speed={.4} growth={6} />
    </Canvas>
  )
}

What is standing in

Four components exist in the Figma file and have no owner in src/components/contract.ts, so they are drawn here as labelled boxes rather than approximated. That is the same rule the Figma push follows in the other direction: a block the contract does not declare becomes a stand-in, never a lookalike, because a lookalike is a design nobody owns and the audit has nothing to compare it against.

Stand-in In Figma To adopt it
Blurb Lockup 10 instances, the article body Declare, record the id, mark the block
Accordion 2 instances, State variant Decide whether it supersedes Details
Widget 1 instance, 1 node Probably page furniture, not vocabulary
Footer 1 instance, plus Footer Navigation ×2 Declare both, or fold the nav into the footer

The masthead, sidebar and on-this-page rail are not stand-ins: Figma draws them with its own Standard, Docs and In-Page Navigation components, and the contract already has Header, Nav and Toc doing those three jobs. Reconciling the two sets is a decision for the next sync, not something this page should quietly pick a winner for.
