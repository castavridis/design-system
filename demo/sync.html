directions.

The design book pushes to Figma, Figma pulls back, and a build-time guard stops either side drifting. This page is the quickstart — the brand book is next door.

Quickstart

Five commands. Each is safe to run repeatedly — the pushes update in place rather than duplicating, and the pull writes nothing until you ask it to.

Command Does
pnpm figma:emit Builds the tokens, then flattens them into dist/figma-tokens.json — the plan every other command reads.
pnpm figma:push Generates the Plugin API script that upserts variables. --scopes=brand,fonts narrows it; --record <result> folds the returned ids back into figma/sync.json.
pnpm figma:page Reads demo/index.html into a page spec and generates the script that assembles it in Figma — every block the contract declares placed as an instance of its component set, never a copy. --snapshot also emits the read-back script.
pnpm figma:pull <snapshot> Three-way diff against the last agreed state. Writes a report to figma/syncs/. Dry run unless you pass --apply.
pnpm figma:audit <snapshot> Compares components against the contract and the page against its own composition. Exits non-zero on drift, so it can gate a pipeline.

Note

Snapshots come from Figma through the MCP tools, which are agent-facing rather than callable from Node. So the capture happens in a session and the scripts consume the JSON — that split is why every decision is testable offline.

The loop

You edit both sides, so conflicts are the normal path rather than an exception. The base advances on every settled write — if it only advanced on pull, a push would leave it stale and the next sync would report a conflict that never happened.

code → figma
  • Edit src/pmndrs-design-book.ts
  • pnpm figma:emit
  • pnpm figma:push, run it, record the ids
figma → code
  • Tweak variables or components in Figma
  • Capture a snapshot
  • pnpm figma:pull, read the report
  • Re-run with --apply when it looks right
the page
  • Edit demo/index.html
  • pnpm figma:page, run it, record the ids
  • Instances follow their components; nothing is redrawn
keeping honest
  • pnpm figma:audit — component and page drift
  • pnpm test — 64 offline tests
  • pnpm typecheck

What the build refuses

Four rules are enforced rather than documented and hoped for. Each one exists because the mistake it catches is invisible — the artifacts all render correctly right up until someone changes context.

Components bind theme slots, never ramp steps

A bare name like tint-blue is a theme slot and must exist in both modes. ramp.blue-950 fails the build: it resolves perfectly and silently locks the component to one mode. Write fixed:brand.purple when a colour genuinely must not change — the prefix is required, because "this one doesn't move" is a decision worth writing down.

Derived tokens are push-only

Ramp steps are computed by rampStops(). A Figma edit to one cannot be expressed in the book and would die on the next build, so pull reports it and refuses. Edit the seed, not the step.

The page instantiates, it never redraws

Where demo/index.html renders a component the contract declares, the Figma page places an instance of that component set. Everything else becomes a labelled stand-in rather than a drawing — a hand-made Figma doc-search would be a design with no owner in code, and nothing to audit it against.

Colours re-author in OKLCH, never bare hex

The book is authored in oklch() deliberately. A pull that wrote color('#00e180') would dismantle that one token at a time while every rendered artifact stayed correct, so the conversion is built in and verified against all nine brand seeds.

Where things stand

Tokens

175 in the book. 118 pushed across five Figma collections, plus a theme collection with Dark and Light modes.

Components

5 of 24 built in Figma — Gha, Button, Badge, Code, Header. All mode-aware, zero unbound paints.

The page

demo/index.html assembled beside its components from 135 blocks: 25 instances, 23 stand-ins, and the swatch and ramp grids drawn from the variables themselves. Move the frame in Figma and the next push follows it — the recorded node id wins over any name.

Not done

figma:adopt for per-component pulls, 19 remaining specimens, and Code Connect — which waits for a React target in @pmndrs/docs.

Files worth knowing

Path Role
src/pmndrs-design-book.ts The only writable source of truth for tokens
src/components/contract.ts Component props and their per-slot bindings. Prop names mirror @pmndrs/docs so the eventual port is generation, not redesign
scripts/figma/page.ts Reads the demo page into blocks. A <pmndrs-*> element or a data-component marker becomes an instance; its props are read back out of the markup rather than restated
figma/sync.json Committed. Variable, component and page-instance ids, the resolution policy, and the last-agreed values a three-way diff needs
figma/syncs/ One reconciliation report per pull
scripts/figma/ Pure logic — reconcile, audit, oklch — with no Figma calls, so it is all testable offline
