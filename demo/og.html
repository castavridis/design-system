Quickstart

Run from the repo root. Every command builds the tokens first, so a card is never rendered against a stale palette. A batch shares one bundle and one browser — five cards cost about what one does.

Command Does
pnpm og -- specs/react-three-fiber.json Renders one spec to og/out/. --out puts it somewhere else.
pnpm og -- specs/site.json --manifest Renders a set. The manifest names an outDir and an out per card.
pnpm og -- --title "Postprocessing" --accent teal No file at all — enough flags to render a card from the shell.
pnpm og -- specs/…json --gif One seamless loop instead of a still. --mp4 for the same motion at a tenth of the size.
pnpm og:studio Remotion Studio — scrub the timeline and edit props against a live scene.
pnpm og:demo Re-renders every asset on this page into demo/og/.

Note

The generator is a workspace package, not part of the published token package — a contributor who only touches src/ never installs React, three.js or a headless browser. It consumes the tokens as pmndrs-design-tokens: workspace:*, through exactly the entry points an outside consumer would use.

The cards

Grouped by the field each one is there to demonstrate. Together they cover every source kind, every scene, both themes, all three sizes and the effect chain — which is the whole surface of the spec.

scenes

A scene is plain React Three Fiber that receives { time, palette, seed } and imports nothing from the renderer. The palette is the accent's eleven-step ramp, so the scene never picks a colour — it picks a step.

themes and sizes

theme chooses which neutral ramp is the ground, and it moves the type and the scene lighting together rather than inverting the artwork. size is a name for a box — width and height override it when a target wants exact pixels.

effects

Bloom, lens fringing, grain and vignette are one chain over the whole frame, media included. Both cards below are the same scene at the same seed and the same second; only effects differs.

sources

Media is drawn as a textured plate inside the scene rather than composited behind the canvas, so a photo card takes the same camera, the same lighting and the same grade as a generated one. That is why these two look like they belong to the set.

motion

--gif or --mp4 renders one loop instead of a still. Every rate in a scene is rounded to a whole number of cycles per loopSeconds, so the last frame leads back into the first — verified rather than asserted: a still at t=0 and one at t=loopSeconds are byte-identical for all three scenes.

Why the GIF is the smaller picture

It is not a fair fight and it is not meant to be: GIF caps at 256 colours per frame and cannot reference the frame before it the way a video codec does. A scene that is mostly gradient and bloom is its worst case, so the box comes down until the file is sane. Everything else about the card is identical.

An animated card is a real option

The Open Graph spec allows image/gif. Whether a platform actually plays it varies, so treat the first frame as the card and the motion as a bonus — which is why atSeconds still picks the frame a still would use and the loop runs from there.

--fps thins, it does not slow

Frames are dropped rather than stretched, so motion keeps its speed — but only whole divisors of 30 are reachable (30, 15, 10, 7.5…). The line the CLI prints is the rate you actually got.

The spec

Plain JSON, so it travels from a file on disk into the browser without anything having to serialise a closure. Only title is required; src/lib/spec.ts fills in the rest and is the one place the defaults live.

A card, in full

An excerpt of og/specs/demo.json — the manifest that renders this page. outDir is relative to the manifest; a card without out is named from its title.

Field Default What it is
title — The headline. The only required field.
eyebrow none Small tracked line above the title.
subtitle none One clause below it. Wraps.
meta none Chip, top right — a URL or a version.
accent purple Any ramp: purple, red, orange, yellow, green, teal, blue, dark, light. A typo stops the render with the list.
theme dark Which neutral ramp is the ground.
size og og 1200×630 · square 1200×1200 · wide 1920×1080. width/height override it.
source scene: ramp-orbit { kind: "scene" | "image" | "video" }. Media takes a src and a fit.
effects bloom 0.9, fringing 0.0016, noise 0.045, vignette 0.5 The grade. Any of them at 0 is off.
wordmark the title behind a scene, none over media 3D type inside the scene, so it takes the light and the bloom. "" always means none.
seed 1 Fixes every random placement. Same seed, same card.
atSeconds 2 Where the card is sampled. For a scene it is a look-picker; for a video it is the timestamp.
loopSeconds 6 The period a scene repeats over. Shapes stills too — rates are rounded to whole cycles of it.

Using a card

A rendered card is a file; the markup is five lines. Below is the card this page declares as its own, and the tags that declare it.

og:image must be absolute

A root-relative path works in a browser and fails in every crawler: the card is fetched from a different origin than the page it describes, so it needs a scheme and a host. This page can't know its deployed origin at build time, so /demo/og.js rewrites the tag to location.origin on load — a real site should write the absolute URL in at build time, where a crawler sees it without running JavaScript.

One render per deploy is enough

Cards are deterministic — same spec, same bytes — so rendering them in CI and committing or uploading the output covers it. There is no request-time image service here, and nothing on this page needs one.

In the document head

twitter:card is what makes the image render large rather than as a thumbnail. Width and height are optional but stop a crawler guessing.

What will bite you

Five failures cost real time to find in building this, and none of them announce themselves. They are written up in full in og/README.md; the short version is here because the first one is a rule you have to follow when adding a scene.

A scene must be a pure function of time and seed

A still is produced by seeking straight to one frame, with no frames rendered before it. Anything that accumulates — useFrame deltas, a THREE.Clock, drei's <Float>, Math.random() — has no history to accumulate from and renders differently every time. Derive motion from time and jitter from mulberry32(seed).

Fonts must be WOFF, not WOFF2

The 3D wordmark is typeset by troika, which parses the file itself and understands only WOFF. Handed a .woff2 it logs once, never calls its callback, and the render hangs until delayRender times out 28 seconds later.

The canvas is drawn once

With frameloop="never" a texture that resolves late never reaches the framebuffer, and instance matrices uploaded from a useFrame are still zero when the capture happens. <Settle> and a layout-effect write are why the cards above are not empty.

And a timer is not a settle condition

Holding the capture open for a fixed window asks how long to wait, not whether anything happened — so when the WebGL context came up slowly, every redraw in the window painted nothing and the capture took a blank canvas. Being a race, it landed on the first frame captured, which for the GIF above is the frame a platform shows as the card. The window is now a minimum, and the release waits for the renderer to report triangles actually drawn.

These files are checked in

The images on this page are the only binaries in the repository, and they are here deliberately: the deploy builds the tokens and assembles the site, but it has no Chromium and no Remotion licence — so cards are rendered on a developer's machine and committed, the same way you would ship the card for your own site.

pnpm og:demo

Five passes: the mp4 loop, its poster, the GIF, then specs/demo.json and specs/demo-media.json — in that order, because the media cards are sourced from what the earlier passes wrote.

--format jpeg

The stills are JPEG at a quarter of the bytes; pnpm og emits PNG by default, which is what you want for a card you actually ship. The GIF is the heaviest file here — sixteen times the largest still, and half again the mp4 it is a smaller copy of.

demo/og/

Copied into the site verbatim by scripts/site.ts alongside the rest of demo/, so what you see locally is what deploys.
